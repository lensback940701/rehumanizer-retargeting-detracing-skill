# Rehumanizer · Retargeting · Detracing（RRD）

**保持idea的学术野心，让人味可测度，在论文施工过程中持续强化与锐化。**

[English](README.md) · [原始v3.4安装快照](downloads/rrd-v3.4-skill.zip) · [Skill完整规范](SKILL.md) · [中文开发测试记录](docs/review-20261005/DEVELOPMENT_TEST_LOG.zh-CN.md) · [已知限制](docs/KNOWN_LIMITATIONS.md)

RRD是在论文施工过程中可反复调用的两阶段学术锐化工具：守住idea的ambition，将人味的若干维度转化为可测度指标，并在已有稿件或章节需要时重定位目标、激活材料、强化论证与叙事。它不是最终结稿或修稿收口skill，不是规避AI检测的工具，也不替代作者的研究判断。

**版本：** v3.4　**使用状态：** 受监督的工作基线　**工程验收加固：** 待完成　**许可证：** 待作者决定，本包未擅自添加。

## 三个核心亮点

### 1. 保持idea的学术野心，终结反复降调与恢复的拉扯

**保持idea的ambition，是RRD的最高编辑原则。** 它不是又一轮先加防御、再去防御的措辞清理，而是将研究目标置于一般文风规则之上，撤销削弱贡献的历史约束，并要求任何新增的弱化都提供具体依据。作者确认了可支持的研究靶点后，后续检查不能仅为了显得更安全而重新压低它；只有新证据或作者明确改变目标，才构成重新讨论的理由。

要保留的是证据能够承载的、最有价值的论证力度，而不是制造确定性。事实、准确引述与真实反证是不变的边界，但不能被泛化为持续退让的理由。去防御化因此成为一次明确的规则纠偏，而不再是逐句反复协商。

### 2. 将人味转化为可测度指标，同时为表达保留弹性

RRD不只要求把文字写得更像人，而是把其中若干维度转化为**可检查、可量化的代理指标**：

| 维度 | 已有测度与检查 |
| --- | --- |
| 句子节奏 | 句长均值、标准差与变异系数，短句占比及连续短促句信号 |
| 材料在场 | 引语与数字密度、可定位引语记录、引述标注负荷 |
| 作者与行动者在场 | 明确立场词、行动者代码等信号，并结合情境化阅读判断 |
| 论证衔接 | 相邻句主题衔接率与关系标记信号 |
| 模板化程度 | 重复段首、固定转换句式、关系动词习惯及非核心标签词扩散 |

**这些人味指标只可统计与诊断，不可硬性规定实现数量。** RRD不预先要求必须出现三条引语、每两句添加一个连接词，或让每段达到固定的作者立场密度。具体措辞、节奏和材料落点交给大模型结合上下文生成，再统计实际形成的数量与分布；它们可以在不同段落和不同运行中自然浮动，不是预先抽取并分配的数量目标。

**指标可测度，表达随机实现，数量不作配额。** 随机性来自模型生成过程本身，而不是额外设置的随机采样器。Skill负责给出研究目标、来源边界、相对于参考写作的诊断信号及实质审读，让人味具有可观察性，同时保留实现方式的弹性。预警用于定位论证断裂、材料失活或表达单调，不用于强迫文本追平某个数字。作者参考写作提供比较依据，而不是每篇稿件都必须复刻的统计模板。

弹性作用于表达；已经确认的研究靶点与对来源的忠实性保持不变。

### 3. 在施工过程中随时强化锐化，而不是负责最终结稿

当idea被改弱、材料与论证脱节、语言重新机械化，或者新洞见要求调整研究靶点时，都可以调用RRD。它既可以处理整稿，也可以针对已明确范围的章节；前提是已有可检查的文本和可访问的支持材料，而不是论文必须接近定稿。

每次调用仍保留**只读诊断→作者授权→按范围修订**的结构。输出是一个更有力度的工作版本，随后返回研究与写作过程。它不宣布项目完成，不认定可以投稿，也不强制转入终稿润色。可以反复调用，不等于应对没有实质变化的稿件不断启动新的修稿循环。

## 主要功能

![问题、核心能力与预期交付物](docs/images/overview.png)

| 功能 | 目标 |
| --- | --- |
| 重定位 | 恢复材料能够支持的最佳研究主张，不机械回到最早、最强或范围最大的版本。 |
| 恢复人的研究判断与表达 | 重读原始材料，恢复行动者、情境、作者立场、解释深度、段落衔接与章节组织。 |
| 清理机械化修订痕迹 | 删除模板化、流程化及不必要的防御性表达，保留必要限定与反面证据。 |

## 快速开始

![四步使用路径](docs/images/quickstart.png)

需要本轮更新后的description与施工期使用指引，请使用`main`分支文件。上方ZIP保留为原始v3.4快照，不包含本轮定位更新；发布清单与存档测试仍对应原始快照。

按照所用agent环境的安装说明，将本目录配置为可访问的本地skill。检查脚本需要Python；Markdown、TXT是最直接的扫描输入，其他文档格式的读取依赖相应组件。完整回归测试使用`python-docx`。

1. 准备当前稿件或指定章节、可用的早期稿、原始材料与作者约束，明确本次改写范围。私有研究资料应放在公开仓库之外。
2. 显式调用`$rehumanizer-retargeting-detracing-skill`，先执行Stage 1，只读诊断，不修改原稿。
3. 作者审阅恢复的研究靶点、拟放宽或保留的约束，以及改写强度，并作出授权决定。
4. 在新的对话中使用生成的Goal与启动提示执行Stage 2。先回读材料和反证、复核靶点，再改写与核验，最后在本轮工作版本完成最后一次修改并导出后重新运行检查，随后返回研究与写作；是否进入终稿润色另行决定。

Stage 1启动示例：

```text
使用 $rehumanizer-retargeting-detracing-skill，仅执行 Stage 1。
只读诊断所提供的稿件或指定章节，不修改原文。
将保持idea的学术野心作为最高编辑原则。
以可测度的人味信号指导修改，不施加固定文风配额。
在本次范围内恢复证据支持的最佳研究靶点，审查既有约束，
生成诊断报告、GOAL.md 与 SHORT_LAUNCH_PROMPT.md。
只询问会实质影响改写路线的作者决策。
将交付视为施工期工作版本，而不是最终结稿决定。
```

在本仓库根目录运行脚本帮助与测试：

```bash
python scripts/trace_scan.py --help
python scripts/defense_gate.py --help
python scripts/final_check.py --help
python -m unittest discover -s tests -v
```

这些脚本负责检查和验证，不会自行调用语言模型、自动完成全文改写。

## 仓库结构与维护

`SKILL.md`是agent入口；`references/`保存八份方法与写作规范；`assets/templates/`保存Goal、登记表和结果模板；`scripts/`保存六个检查脚本；`tests/`保存合成回归测试；`docs/`保存六张图、历史审查记录与已知限制。

事实、来源保护、匿名、知情同意和反证要求不因改写而放宽。不得虚构引用、数字、动机或结果。公开报告问题时应使用合成或已获适当授权的材料，不上传未发表稿件和参与者资料。

建议将写作策略修改与工程修补分开提交，为缺陷增加复现测试，不通过放松检查配置制造PASS。

## 本轮定位更新

本轮更新description、调用指引和中英文README，前置突出学术野心优先、可测度的人味与施工期可重复锐化。未修改扫描脚本、门禁、测试集和原始下载ZIP，未另加采样器，也未产生新的稿件评测结果。随机实现是对既有生成方式的明确表述，不是缺失功能或新增算法。历史47项测试结果仍对应原受检v3.4快照。
