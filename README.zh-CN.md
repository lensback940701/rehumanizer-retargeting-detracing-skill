# Rehumanizer · Retargeting · Detracing（RRD）

**保持idea的学术野心，让人味可测度，在论文施工过程中持续强化与锐化。**

RRD是在论文施工过程中可反复调用的两阶段学术锐化工具：守住idea的ambition，将人味的若干维度转化为可测度指标，并在已有稿件或章节需要时重定位目标、激活材料、强化论证与叙事。它不是最终结稿或修稿收口skill，不是规避AI检测的工具，也不替代作者的研究判断。

## 三个核心亮点

<p align="center">
  <img src="docs/images/core-highlights-art.png" width="100%" alt="RRD的三个核心亮点：保持学术野心、可测度但不配额化的人味，以及施工期锐化。" />
</p>

RRD以三个原则组织修订：保护idea的学术野心，让人的学术表达可观察而不被公式化，并在研究与写作仍在推进时强化稿件。这三个原则分别回答：它要保护什么、如何诊断问题，以及应当在何时使用。

### 1. 保持学术野心，作为最高原则

**保持idea的学术野心，是RRD的最高编辑原则。** 它追求的不是让稿件显得更安全、更圆滑、更不容易被挑错，而是恢复既最有研究价值、又真正得到证据支持的学术主张。

因此，RRD不止于清理防御性措辞，而是要终结**软化—恢复—再软化的反复拉扯**。作者确认了可支持的研究靶点后，后续检查不应仅为了显得更谨慎，再次默默将其压低。重新讨论靶点，需要新的证据依据或作者明确改变目标，而不是对安全表述的泛化偏好。

事实准确、引述忠实与真实反证始终是不变的边界，但不能被转化为持续降低学术野心的理由。重定位负责恢复论证方向；撤销不必要的防御性约束，则防止后续检查将已经恢复的主张再次削弱。

### 2. 将人味转化为可测度信号，但不将其配额化

RRD将人味的若干维度转化为**可观察、可测度、可比较的代理指标**。它不把人味留在模糊的审美判断中，而是具体检查句子节奏、引述密度、作者立场、段落衔接、表达多样性与模板重复等信号。

**这些指标只可统计与诊断，不可硬性规定实现数量。** RRD不会预先要求稿件必须出现三条引语、每两句添加一个连接词，或达到固定的立场表达密度。模型依据研究目标与上下文生成措辞、节奏及材料落点，再对实际形成的数量与分布进行统计和审读。

**指标可测度，表达随机实现，数量不作配额。** 随机性属于模型的生成过程，而不是由额外采样器预先分配文风数量。作者参考写作提供比较依据，不是每篇稿件都必须复刻的统计模板。预警用于定位论证断裂、材料失活与表达单调，不要求文本为追平某个数字而增删内容。

目标不是制造通用的人味分数，而是使若干写作问题更容易被发现和修复，同时保留表达的生成弹性。事实、引语、来源忠实性与已经确认的研究靶点不随机化。

### 3. 它不是最终结稿工具，而是施工期的锐化工具

**RRD服务于写作过程中的强化与纠偏，而不是最终结稿。** 当idea被改弱、材料与论证脱节、语言重新机械化，或新洞见要求重新校准研究靶点时，都可以将它带回工作流程。

它可以贯穿起草、修订与重新思考，既作用于整篇稿件，也作用于明确范围的章节。前提是已有可检查的文本和可访问的支持材料，而不是论文已经接近投稿。每次调用仍遵循**只读诊断→作者授权→按范围修订**的结构。

每轮输出都是更有力度的工作版本，随后返回研究与写作过程。它不宣布论文完成，不认定可以投稿，也不强制转入终稿润色。反复调用应当回应实质性的研究与写作需要，而不是对没有变化的稿件不断开启修稿循环。

**以学术野心定向，以可测度信号诊断，以施工期锐化明确工作定位。**

| 功能 | 目标 |

## 快速开始

![四步使用路径](docs/images/quickstart.png)

需要本轮更新后的description与施工期使用指引，请使用`main`分支文件。上方ZIP保留为原始v3.4快照，不包含本轮定位更新；发布清单与存档测试仍对应原始快照。

按照所用agent环境的安装说明，将本目录配置为可访问的本地skill。检查脚本需要Python；Markdown、TXT是最直接的扫描输入，其他文档格式的读取依赖相应组件。完整回归测试使用`python-docx`。

1. 准备当前稿件或指定章节、可用的早期稿、原始材料与作者约束，明确本次改写范围。私有研究资料应放在公开仓库之外。
2. 显式调用`$rehumanizer-retargeting-detracing-skill`，先执行Stage 1，只读诊断，不修改原稿。
3. 作者审阅恢复的研究靶点、拟放宽或保留的约束，以及改写强度，并作出授权决定。
4. 在新的对话中使用生成的Goal与启动提示执行Stage 2。先回读材料和反证、复核靶点，再改写与核验，最后在本轮工作版本完成最后一次修改并导出后重新运行检查，随后返回研究与写作；是否进入终稿润色另行决定。

Stage 1启动示例：

```text
使用 $rehumanizer-retargeting-detracing-skill，仅执行 Stage 1。
只读诊断所提供的稿件或指定章节，不修改原文。
将保持idea的学术野心作为最高编辑原则。
以可测度的人味信号指导修改，不施加固定文风配额。
在本次范围内恢复证据支持的最佳研究靶点，审查既有约束，
生成诊断报告、GOAL.md 与 SHORT_LAUNCH_PROMPT.md。
只询问会实质影响改写路线的作者决策。
将交付视为施工期工作版本，而不是最终结稿决定。
```

在本仓库根目录运行脚本帮助与测试：

```bash
python scripts/trace_scan.py --help
python scripts/defense_gate.py --help
python scripts/final_check.py --help
python -m unittest discover -s tests -v
```

这些脚本负责检查和验证，不会自行调用语言模型、自动完成全文改写。

## 仓库结构与维护

`SKILL.md`是agent入口；`references/`保存八份方法与写作规范；`assets/templates/`保存Goal、登记表和结果模板；`scripts/`保存六个检查脚本；`tests/`保存合成回归测试；`docs/`保存配图、历史审查记录与已知限制。

事实、来源保护、匿名、知情同意和反证要求不因改写而放宽。不得虚构引用、数字、动机或结果。公开报告问题时应使用合成或已获适当授权的材料，不上传未发表稿件和参与者资料。

建议将写作策略修改与工程修补分开提交，为缺陷增加复现测试，不通过放松检查配置制造PASS。
